# Settings redesign — Codex proposal

7 November 2026. Design only; no application changes. Baseline: `754c93bdc88e52ae7c00684052522b21dbc2c151`.

## 1. Intent, authority and evidence

Make personal choices easy to find, brief to read and reversible, without letting a preference conceal a changed result or change the mathematics unnoticed. Settings opens from every page and leaves that page mounted.

**Owner requirements:** the V2 task brief, COMMON.md, today's owner message and the settings/level/remembering messages of 4–6 November supplied with the brief. The owner explicitly asks for a toggle for joint-list party seats, separate zero-seat filters, concise bilingual labels and help behind (i), and settings appropriate to each level. The existing reference/custom-level design and decision 0013 supply the starting model, not evidence that this new proposal has been accepted.

**Observed in source:** the inventory below cites the baseline source, with line numbers locating the relevant behavior, not necessarily every consumer. Paths beginning `components/` mean `src/app/components/`; `store.ts`, `features.ts`, `format.ts`, `styles.css` mean files under `src/app/`. Source inspection covers the tool registry, all tool entry points and their shared controls. No sounds or candidate-photo renderer were found in `src/app`; neither should acquire a pretend working setting.

**Observed in the running app:** used a worktree Vite server on port 5197, with the existing project dependencies and a local scratch cache. Walked the 15 registered tools and Custom at all four levels on k26, including a Custom based on Simple exposing charts, localities and chamber options. Also traversed k25 and k1 at the four levels at phone width. Some first visits briefly rendered lazy-loading content; the longer combined traversal exceeded the browser tool's 15-second response window, although the page subsequently reached its final k1 state. A subsequent warm traversal completed all 16 destinations at each level on k26 (64 visits, no lazy-loading placeholders). This is exploratory coverage, not a completed regression suite or a claim to have exercised every nested action. Inspected the actual Settings dialog in English/light at 1280×800 and Hebrew/dark at 390×844, and both owner screenshots. The source establishes defaults; persisted browser values are not evidence of factory defaults. The scratch server used a dependency symlink; Vite blocked self-hosted font files outside its default allow-list, so these inspections used fallback typography and cannot validate final text metrics. Fast tool changes also produced existing nested-dialog markup warnings and Leaflet clearRect teardown errors; these are observations for the coordinator, not Settings fixes. No 1500/1024 visual pass, screen-reader audit or implementation test was performed for this written proposal.

**Proposed below:** labels, defaults, schema and interaction changes are designer recommendations. The coordinator must reconcile them with the independent Claude design before implementation. No external electoral facts are introduced by this design.

## 3. Recommended design and alternatives

Use **one searchable dialog, with six ordered sections and the existing Custom feature registry**. All rows apply immediately; no Save/Cancel draft. Close means return to work, not undo preferences. Each row has one short label, one stateful control and an optional (i). No explanatory paragraphs in the normal scan path.

Alternatives considered: (a) separate settings per level would duplicate keys and produce conflicting values; (b) one exhaustive flat list would make Simple overwhelming; (c) nesting display settings inside each tool would make global preferences hard to recover. The recommendation gives one value per preference and level-aware visibility, plus local shortcuts pointing to the same row. This is the designer's recommendation, not an owner-selected implementation.

Groups, in order: **General / כללי**, **Lists & parties / רשימות ומפלגות**, **Charts / תרשימים**, **Editing / עריכה**, **Remembered answers / תשובות שמורות**, **Reset / איפוס**. General includes number format, interaction and display. Custom feature rows remain on the existing Custom page; a Settings button opens that page after closing the dialog and can return to the same Settings row. Do not cram the entire feature catalogue into the popup.

### Level rules

Below, **All** means Simple, Standard, Expert and Custom; **S+** means Standard and Expert; **E** means Expert. Custom shows All plus rows relevant to features marked show or collapsed in its registry, and rows of its base preset. For example, a Simple-based Custom with `charts:show` shows chart defaults; one exposing `chamberOptions` shows geometry/colour controls. Hidden advanced rows with non-default values get a quiet count link: **Other active settings (n) / הגדרות פעילות נוספות (n)**. It expands those rows in place without changing level. Search also finds every setting, labeled with its normal level. Users never need to switch mode merely to undo an active preference.

**Hidden controls never reset or override values.** Presets only change visibility. This intentionally replaces forced `useDigits()` and chamber defaults and the historical Simple-only balancing override where they conflict with this requirement. A new Simple user gets Hebrew, system theme, compact density, two decimal places, arc/list colours, party seats On, zero-seat parties hidden, familiar list-tail folding, automatic motion respecting OS, deliberate safe help, and Ask for vote-source decisions. A saved answer remains active in Simple and is shown beside the edit in a short source label. Never silently use another source because its control is hidden.

### Control grammar and exact setting copy

Keys below are stable proposed IDs under a versioned personal-settings record. **T** is a switch: genuinely binary; **G** is a segmented radio group for 2–4 options: every option visible; **D** is a searchable/select picker for many choices. Translated option order follows the written order; numeric segments and chart geometry stay LTR. Choices are fully labeled, no ambiguous icons. (i) text is complete below. A row hidden by dependency remains mounted/disabled with its value visible if it was visible before the dependency changed, so it does not jump away.

## 4. Remembered answers and asking at use

This is a scope-aware answer manager, not a miscellaneous checkbox pile. The global defaults above and this manager are two views of the same answer registry. Remove today's misleading “Clear all answers” that only clears item answers.

## 6. Reset scopes and saved work

Reset section offers **Reset display / איפוס תצוגה**, **Clear answers / ניקוי תשובות**, **Reset level / איפוס רמה**, **Reset all settings / איפוס כל ההגדרות**. Show a count and exact scope before applying each. These are action buttons, not settings controls.

- Reset display: resets density, motion/flash/help/preview, numeric/date/name formats, logo/candidate display, all list filters/sort, chart preferences and view defaults, tips and success notices. Keeps language, theme, level, saved answers, stored step choices and community-loading choice. Joint-party view default is included but never overwrites encoded saved/scenario choices.
- Clear answers: choose **This question / שאלה זו**, **This election / בחירות אלה**, or **All answers / כל התשובות**; searchable question/election pickers only when needed. Clears matching global defaults where applicable plus item/session exceptions, and reports their count. Current election scope does not delete a global default; say this explicitly. Does not change an edit already committed. Stored step sizes have a separate **Clear step sizes / ניקוי גודל צעדים** action with help **Restores each quantity's initial step. / שחזור הצעד הראשוני לכל סוג גודל.**
- Reset level: choose Simple/Standard/Expert; removes Custom visibility overrides only. It does not reset any setting's value.
- Reset all settings: returns personal preferences, global answers, item/session exceptions, step sizes and Custom visibility to fresh defaults. Keeps the current language and theme so the confirmation remains understandable. The confirmation explicitly lists those retained choices; resetting either is available on its own row. It does not delete scenarios, workspace recovery, family definitions/catalogue, family-specific counting interpretations, voter groups, exports, or election appearance records. It resets Families' table-first display alias but not family analysis policy.

Confirm copy: **Reset {scope}? / לאפס את {scope}?**, **Your saved scenarios stay. / התרחישים השמורים נשארים.**, buttons **Reset / איפוס**, **Keep / להשאיר**. Clear-answer confirmation says **Clear {n} answers? / לנקות {n} תשובות?**. “This question” removes all its exception scopes; show affected elections, not only the currently loaded one. Reset operations are atomic personal-setting changes, with a single **Undo reset / ביטול האיפוס** until another settings mutation or closing the dialog. Failure to persist must show **Not saved in this browser / לא נשמר בדפדפן זה** and keep the session change usable; no success claim. Do not clear storage wholesale.

## 7. Migration without lost choices

Use `israel-elections:settings:v2`, `{version:2, values:{…}, answers:{defaults,items,session}, steps:{…}}`; session answers live in memory only and are excluded from serialization. Keep feature visibility keyed by existing feature IDs. New settings derive from the one registry (key, default, bilingual label/help/options, level/dependencies, persistence and migration); no second hand-maintained level list. Existing scenario schema/action classes and unrelated storage stay unchanged.

Migration is idempotent: a valid v2 value wins; fill only missing v2 keys from legacy; validate before writing; write new record successfully before considering migration done. Leave old records intact for recovery, but v2 readers must not resurrect a value the user later reset. An explicit completed-version marker/tombstone distinguishes intentional defaults from missing migration. Failed persistence leaves legacy storage readable and the current session functional. No scenario rewrite is part of migration.

| Legacy source | v2 destination and precedence |
|---|---|
| `israel-elections:v1.lang`, `.theme` | `language`, explicit light/dark `theme`; do not turn a saved theme into System. Missing theme → System. |
| `.level`, `.customFeatures` | Same base and exact known visibility entries; explore→Simple, advanced→Expert as today. Preserve valid overrides, including base preset. Unknown IDs retained as inert extension data, not interpreted. |
| `.digits` | `digits` exactly when one of seven supported values; otherwise fall back to 2 with recovery evidence kept in legacy. It now applies at all levels; this is an intentional correction to visibility semantics. |
| `.showComponentSeats` | `componentColours`; explicit false survives. Absent → On. |
| `.hintDismissed` | `showTips = !hintDismissed`; preserve dismissed hints. |
| `.markOfficial` plus `israel-elections:preferences.comparison` | Explicit valid `comparison` answer wins; official→Official, reference→Loaded. If absent and `markOfficial=true`, preserve Official. If false/absent with no saved answer, preserve Ask; false alone is not proof of an explicitly remembered Loaded answer. |
| `israel-elections:preferences.voteSource` | `voteSourceDefault` for new/proportional; absent→Ask. Named `t:id` retained as legacy conditional donor answer, never dropped or reused across elections without validation. |
| `israel-elections:vote-source` | Fallback only when newer preference record has no valid vote-source answer; ask/new/proportional map directly. |
| `israel-elections:preferences.jointSeats` | Existing explicit on/off wins exactly. Existing installation with no saved key stays Off to preserve its baseline; truly fresh v2 installation gets proposed On. Do not confuse `showComponentSeats` with jointSeats. |
| `israel-elections:item-preferences` | Preserve every valid `voteSource:kN:list:id` or `voteSource:kN:bloc:id` and donor answer, maintaining election scope. Unknown/missing entities remain inactive records, not deleted. |
| In-memory `preferenceFor` comparison records | Copy to session answer map and retain current reference; do not serialize them accidentally. Current behavior promises only session lifetime. |
| In-memory `layout`, `colorBy` | If upgrading a live session, copy to `chamberLayout`, `seatColour` when v2 absent. Cold reload has no stored values: Arc/List. |
| `israel-elections:families:exact` | True → table-first `analysisView` for migration. Preserve an existing explicit v2 Charts choice. Keep an alias until Families uses the shared setting; no two competing toggles. |
| `israel-elections:families:policy`, family catalogue | Leave policies and definitions untouched, accessible through their local editors and Settings search destination. They are interpretations, not display defaults. |
| Saved scenarios, workspace, appearance and voter-group storage; gallery cache/retry keys | Untouched. Their schema, captured faction baseline, historical dates, colours, IDs and logs are not preference migration. |

New filters have no earlier saved choice. For migrated installations use zero-seat parties On and parties-in-seatless-lists On to preserve current visible coverage; for fresh users propose both Off. Other missing settings use the catalogue defaults. Reset display explicitly adopts the new-user defaults; help says **Restores the new defaults / שחזור ברירות המחדל החדשות**. This avoids pretending that no key means the user chose to hide existing rows. Existing list-tail behavior remains Nearby, logos On, text edit marks, gallery On and hover On. No new sound/photo preference is stored.

Before applying a migrated answer, check it against the current election/scenario. IDs may contain colons: do not naïvely split away entity suffixes. Scope identity must include question, election, kind and stable entity ID; scenario-session answers additionally use scenario ID. References to unsaved custom items survive workspace restoration when that item exists, without becoming globally valid. An old duplicate/global answer does not delete a more specific one.

## 8. Fixed safeguards, scope boundaries and acceptance cases

Always fixed: truthful scenario identity; visible edits to factual/analysis fields under the established A/B/C classification; official-vs-scenario distinction; exact/sampled qualifiers; unpublished/provisional and missing-data warnings; relevant lottery warnings; accessible names, focus, contrast and reduced motion; LTR numeric controls and graphics; source status; exact allocation and majority arithmetic. Pure appearance (class C) remains appearance and unmarked as a factual edit. A palette toggle cannot change grouping membership. Personal reset cannot restore votes, candidates or electoral law.

Per-election/scenario: actual votes, turnout, rule variants, surplus agreements, list identity/topology and roster, chosen lottery winner, bloc/family membership and coalition assumptions, authored colours and names, explicit faction views and comparison sides. Their local editors stay authoritative and retain undo/save/share semantics. The Settings search can link to them. Political interpretation cannot hide inside an innocent-looking display preference.

Implementation acceptance, not tests performed by this design task:

1. Fresh versus legacy storage produces the documented defaults; every old explicit false, digit setting, language, Custom override and answer is retained. Corrupt/blocked storage neither destroys work nor claims it saved.
2. k25 Religious Zionism: party seats On shows recorded 7/6/1. Zero-seat parties Off hides the two known zero-seat rows, not a holder or an unknown. It never assigns constituent vote totals. Explicit local reveal restores all constituents.
3. A zero-seat parent and a represented parent exercise the two party filters independently; zero-vote, withdrawn, selected, reference-only and newly edited lists remain correctly qualified/reachable. Filters never alter calculations or exports.
4. Choose Blocks/Bloc colours/eight digits, then Simple and two Custom configurations: values continue working, advanced controls thin out, active exceptions remain discoverable. No rule change or scenario tint results.
5. Save a per-election item answer, then alter global default: the exception remains and wins. Another election does not inherit the item or donor. Missing/withdrawn donors ask again. Canceled action creates no remembered answer or undo entry.
6. Test every reset scope, counts, Undo reset and storage failure; saved scenarios, family interpretations, colours, workspace and voter groups survive. Unrelated legacy records are byte-for-byte unchanged.
7. Search English and Hebrew aliases for zero seats, motion, donor and threshold. Advanced settings and local editors are distinguished. Resetting/filtering/searching/changing language preserves focus and dialog anchor.
8. k26/k25/k1, all levels, Hebrew/English, light/dark, 1500/1024/390, browser zoom and reduced motion: inspect overflow, popovers, phone keyboard, sticky header, stable page scroll and return to the original drawer. Run contrast checks, keyboard and screen-reader review; automated passes alone do not establish conformance.
9. Hover off blocks unsolicited popup/step preview only; Info, changed-value details, restore and exact tables remain keyboard/touch accessible. Changing motion does not suppress persistent edits or error notices.
10. Preview preferences have no logged edits; conditional controls retain values; export images carry chosen display plus essential identity/provenance; CSV/JSON retain exact complete data.

The V2 implementer should integrate the shared settings registry with V1/V3/V4 owners without editing their rendering or comparison behavior independently. This document makes no new map-source recommendation and settles no pending Learn/Play or constituent-vote-attribution research.

## 9. Owner taste questions only

These are non-blocking recommendations for the coordinator to present alongside the other design. Technical issues above should be resolved by implementation evidence, not owner ratification.

1. **New-user party seats On or Off?** Recommend On with zero-seat constituents Off: shows real parliamentary diversity without the owner's unwanted tail. Preserve all existing and shared choices.
2. **Compact or comfortable default spacing?** Recommend Compact to retain the established board, with Comfortable available at every level. Phone targets remain comfortable either way.
3. **Hover or click default for help?** Recommend Hover on pointer devices with click/keyboard/touch always supported, plus a prominent Click preference. No hover-only functionality.
4. **Text or symbol edit marks by default?** Recommend existing short text; Symbol is a permitted alternative only if every edit stays visibly and accessibly marked. No Off option.
5. **Expose Community scenarios at Simple?** Recommend retain its current visibility and default On for existing users; thinning Settings must not silently hide an entire feature. A local Settings shortcut provides opt-out.

## 10. Ten principal improvements over today's popup

1. A true switch for party seats, distinct from component colours.
2. Independent filters for zero-seat constituents and constituents of seatless lists.
3. Separate whole-list, zero-vote and withdrawn visibility.
4. Level-aware controls with hidden values still honored and discoverable.
5. Searchable groups with short, fully bilingual labels and complete (i) help.
6. Density, motion, hover, logos, naming and numeric/date presentation preferences.
7. Chamber and analysis defaults using the same values as local controls.
8. A complete remembered-answer manager preserving exceptions and election scopes.
9. Explicit reset scopes that preserve scenarios, evidence and authored content.
10. Lossless, idempotent migration with explicit old/new default distinctions.
