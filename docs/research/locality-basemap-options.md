# Localities basemap decision — R1

**Recommendation: OpenFreeMap Positron (light) and Dark, with provider place-name layers removed and our retained CBS locality labels in both languages. Fallback: a versioned Protomaps PMTiles regional extract on Cloudflare R2, using the same label policy.** This gives quiet backgrounds, actual dark styling, no exposed paid API key and control over names. Do not ship the unmodified OpenFreeMap style: its bilingual OSM labels do not meet the owner's requirement.

Research date/access date for every external source below: **6 November 2026**. Prices are USD before tax, a snapshot rather than a quotation. Scope: a public GitHub Pages application, no application backend, up to 50,000 map initializations/month. Selection tests: naming control first; then licensing, cost, readability, continuity and integration effort. No production files changed. **Important limits:** account-gated providers were not tested with borrowed/demo credentials; their individual locality spellings remain unverified. PMTiles extract byte size is not measured. These gaps prevent a blanket claim that every provider's live labels or free quota is suitable.

## 2. Names: what is actually proved?

**Language selection alone does not enforce Israeli official names.** OSM `name` follows local usage; `name:he`/`name:en` are community translations, not a CBS contract. A renderer's fallback to `name` can restore Arabic or a different transliteration. The sampled Ma'ale Adumim feature even lacks `name:he`, despite its Hebrew `name`; strict language-only expressions can therefore hide valid Hebrew names. Our CBS layer avoids both problems. Never fix this by editing OSM data to suit our UI.

The live OpenFreeMap `place` source was inspected in MapLibre using `querySourceFeatures` (loaded viewport only). The stock Positron expression concatenates `name:latin` and `name:nonlatin` when available, otherwise uses `name_en`/`name`. It **does not follow our he/en switch**. Bright/Liberty/Dark share the source, but individual style collision/zoom rules can suppress a name; source presence is not proof it is visible on every frame.

**Per-provider verification status:** OSM standard is the same raster in Hebrew and English UI; our English overlay changes only foreground locality names. OpenFreeMap live source/default samples and mock-ups are retained below. Protomaps supports the two tags in its [localization schema](https://docs.protomaps.com/basemaps/localization), but an actual regional archive was not extracted/tested. MapTiler, Stadia, Esri Location Platform, CARTO, Thunderforest, Mapbox, Google/Azure, GovMap and Israel Hiking **have not passed a per-location, both-language tile audit in this lane**. Do not infer they show Jerusalem, settlements, Arab localities or countries correctly merely because their data is OSM-derived or their API offers Hebrew. Esri keyless English-only reference labels were reported in the existing 5 Nov research, not newly verified here.

That is a material evidence gap in the requested exhaustive verification, not a negative finding about those providers. No accounts were created, no email was submitted, no auth was bypassed. The recommended method removes this uncertainty for mapped Israeli localities: disable provider locality text and render `row.nameHe` / `kNN-locality-names.json` by CBS code at all zooms, keeping collision avoidance. For other map names use **strict** `['coalesce',['get','name:he'],'']` in Hebrew and the equivalent `name:en` in English, with a reviewed override dictionary. Do not add `name` as a fallback. Retain road-number shields. Pin styles locally rather than depending on upstream layer IDs staying constant.

Country names need a small reviewed bilingual layer or vetted source expression; CBS locality names do not cover foreign countries. Territorial labels/boundaries are separate from language and must be reviewed explicitly, including Palestine/West Bank/Golan; suppressing all symbols in the prototype omits them rather than deciding policy. For full guarantee, suppress provider place/POI/street names and use only reviewed labels. This sacrifices street-name context but avoids hidden competing names. MapLibre Hebrew symbol text requires RTL plugin/font handling; existing DOM/Leaflet labels use browser shaping and avoid that dependency. [Protomaps RTL requirement](https://docs.protomaps.com/basemaps/localization), [Esri languages](https://developers.arcgis.com/rest/basemap-styles/languages/), [Mapbox language/fallback](https://docs.mapbox.com/help/dive-deeper/maps-internationalization/).

Hebron (3400) lacks usable retained coordinates throughout. Six additional k16 codes (50, 781, 1062, 1273, 1306, 1308) are unmapped. Missing dots are disclosed, not guessed. Envelopes have no geography. Counts prove placement coverage, not correctness of every underlying vote or point.

Positions are CBS ITM reference points transformed from EPSG:2039, joined by code only. Nearest source year is preferred (earlier on ties), then another year if needed. Historical dots can therefore use a later reference location. Source grid precision can be 100 m; stated transformation accuracy ~0.5 m is **not** overall point accuracy. These are not polling stations, town boundaries, precise residences or historical extent. Three PROJ comparisons test conversion numerics, not all real-world localities. Election results are local static assets, not fetched from tile providers.

Colour reliability depends on interpretation: historical votes are coloured using the current scenario grouping. National vote edits are not distributed spatially. Splits use national vote or seat proportions, not measured constituent-party votes. The feature is useful for “how this locality voted, under this grouping,” not predicting neighbourhood or counterfactual votes.

**Failure boundaries:** if OSM blocks tiles, the current Leaflet map still draws election dots, search, selection and results; the existing tile-error message explains missing background (its counter only detects complete initial failure, not all partial outages). Photon is independent: explicit address searches can fail or return inaccurate alternatives, but locality-name/code search and result data remain local. The 1.1-second per-page guard is not a site-wide limit, and 50k map visits says nothing about actual geocoding load. Nearest reference point uses straight-line distance, not administrative containment. [Photon public demo policy](https://github.com/komoot/photon#demo-server) permits reasonable use, without guarantees. If vector loading fails, ensure a locally available empty style can still initialize the map/dot source; otherwise migration could weaken today's graceful failure. WebGL denial/context loss is an additional MapLibre risk: keep the table and locality search usable without a canvas.

## 5. Implementation, size and mock-ups

**Smallest migration:** retain Leaflet markers/tooltips/search and existing collision-aware labels; add `maplibre-gl` + `@maplibre/maplibre-gl-leaflet` as background renderer, with locally retained light/dark style JSON. [Official integration guide](https://openfreemap.org/quick_start/) includes the Vite worker setup. Remove the raster tile layer and CSS inversion, enable CBS labels in Hebrew at all zooms, add reviewed country labels, and preserve attribution. Touch `src/app/components/LocalityMap.tsx`, its stylesheet, `package.json`/lockfile, local styles under `public/`, and relevant map e2e tests. No data-result changes required. A full MapLibre rewrite can use a GeoJSON circle layer and feature IDs for selection but needlessly expands the first change.

**Engineering estimate, not measured bundle:** current Leaflet is roughly tens of KB compressed (~40–50 KB JS); MapLibre plus worker is typically several hundred KB compressed (~250–450 KB depending on version/build), plus styles/fonts/sprites and actual tiles. The bridge keeps both libraries, so lazy-load this tab. Measure the Vite output delta after pinning packages; do not promise a measured saving. Expect 1–2 days for bridge/style/labels/failure handling and focused regression checks; several days for PMTiles hosting/update workflow. WebGL mobile behaviour, Hebrew rendering, style-switch selection retention, blocked tile/glyph requests and table fallback are acceptance checks, not solved by screenshots.

**PMTiles hosting:** define the extract first. Proposed bbox `33,29,37,34.5` covers Israel, Palestinian territories and nearby parts of Egypt/Jordan/Lebanon/Syria, **not whole neighbouring countries**. Use z0–12 initially and overzoom for context; z15 adds street detail and much more data. Full planet is documented at ~120 GB z0–15; each extra maximum zoom roughly doubles size. A regional extract could be tens/hundreds of MB, potentially >1 GB with broader neighbours/high zoom; **no defensible exact regional size was established**. Do not put a guessed number into storage/release commitments. Extract a pinned build with the official CLI, retain bbox/maxzoom/version/checksum and measure bytes before choosing host. No multi-GB extraction was performed merely for this survey.

GitHub Pages is a static host but not automatically a suitable PMTiles host: verify actual `Range`→`206`, stable ETag, CORS/content length, and caching on the published URL. [Pages limits](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits): 1 GB published site, 100 GB/month soft bandwidth; Git's per-file limits also matter. At 50k visits × 2 MB of map transfer, the map alone reaches 100 GB. Do not assume an LFS pointer is a served archive. R2 is [Protomaps' recommended storage](https://docs.protomaps.com/pmtiles/cloud-storage); public custom domain/CDN, Range/CORS including exposed ETag, immutable versioned archive, and self-hosted font/style assets can keep the application backend-free. Raw `r2.dev` development endpoint is not the production serving plan. Each uncached range fetch is a Class B read, not a whole-archive transfer. Free-tier fit depends on measured traffic; refresh/extraction work and operations are not free labour.

Mock-up: `.backup-scratch/r1/prototype.html`, generated by `build-prototype.py` from retained **k25** assets, uses MapLibre **5.6.1**, actual 1,214 positions, **illustrative colours, not party-semantic results**, OpenFreeMap real tiles, browser-shaped DOM CBS labels. It removes all symbol layers, including countries/roads/POIs; labels can overlap in this intentionally small prototype.
