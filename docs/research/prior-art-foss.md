# Prior art: election explorers, simulators and explanatory tools

Research date: **4 November 2026**. App baseline: `6523543e6675577e10e9442f8e8b9011dff04968`.

The best strategy is to copy **specific successful interactions**, not replace this app with another project's architecture. Parliament Seats is the closest product reference; Nicky Case is the strongest teaching reference; Votelib is the strongest exact-engine cross-check. None is a replacement for the historical Knesset engine.

An important finding is that **public GitHub code does not necessarily mean FOSS**. The twelve principal studies below include eight projects with FOSS/public-domain declarations and four explicitly labelled restricted or unlicensed comparators. OWID's current Grapher is no longer MIT; the Israeli map's website is not open source; the vote-transfer explorer is noncommercial; Senedd has no licence grant found. They remain useful references, but not code donors. USA Election Map was also cloned and inspected, then excluded from the principal twelve for its missing licence and weaker system fit.

Evidence notation throughout: **C** = observed in the pinned source; **R** = observed in a running browser or executed library; **D** = author's documentation, not independently validated; **I** = recommendation/inference. Code paths are relative to the pinned repository tree in the inventory. Absence means *not found in the inspected scope*, not proof of global absence. Stars and push times are API observations, not quality or adoption scores. No accessibility conformance or performance benchmark is claimed.

### P1 — Parliament Seats: closest complete product reference

[Repository](https://github.com/disfordave/parliament-seats) · [running app](https://parl.hsw.is/). **AGPL-3.0-or-later: ideas only for this MIT app; do not paste or port implementation code.** Assets/dependencies need separate checks.

**Observed C/R:** React/TypeScript/Vite, Zustand, Nivo and Motion. `src/utils/allocateSeats.ts` is independent of React; `shareLink.ts` implements deflate-raw fragment sharing, JSON validation through `parseParliament.ts`, and a chart-only iframe link. The generated resize listener checks origin and iframe source. `drawImage.ts` defines 1080-square, 4:5, 9:16 and wide output, rather than screenshotting the DOM. Separate tests cover allocation, share links, parsing, export dimensions and language paths. `src/lib/zustandStore.ts` holds several small mutable stores; a replayable scenario history was not found there.

The running desktop app showed a large half-donut, one straight seat bar with majority tick and selected total, immediate party toggles, sort-by-name/position/seats and a View/Edit choice, with parliament presets alongside. It communicates coalition arithmetic faster than our separate tool navigation. Code and README expose responsive layouts and six language files, but no Hebrew/RTL evidence was found in the inspected files. Mobile and keyboard interaction were not exercised.

**Learn:** compose a publication figure, make coalition selection and its answer adjacent, and offer a minimal embed with an “open full app” route. **Avoid:** its generic sample data as historical authority; deterministic “more votes, then first listed” ties as Israeli law; Number arithmetic as a substitute for bigint; multiple independent stores as an improvement over our one scenario. Our compressed sharing already achieves its central privacy benefit. Small star count does not negate unusually close feature fit.

### P2 — To Build a Better Ballot: copy the lesson structure

[Repository](https://github.com/ncase/ballot) · [public article](https://ncase.me/ballot/). **CC0-1.0**, confirmed in `LICENSE`; original covered code/assets can be reused, but independently check bundled/vendor material. Courtesy attribution remains sensible.

**Observed C/R:** cloned static article loaded locally. `index.html` interleaves prose and embedded examples; `play/js/main_sandbox.js` limits features per example and saves system, candidate positions, voter positions and description into a shareable model. `Model.js` owns canvas, mouse, draggable candidates/voters and reset; `Election.js` counts and writes explanatory HTML captions. This is deliberately *not* a clean engine/UI boundary like ours. The article's wide heading, large text and substantial introductory note were visible in the browser; the code provides the embedded draggable teaching models. I did not execute every model interaction.

**Learn:** one surprising result per small experiment; controls appear next to the result they explain; users can predict, manipulate, reset, and only then enter the general sandbox. Apply this to threshold exclusion and the agreement pair's internal division. Our current walkthrough's real allocation trace is a better underlying source than a second toy algorithm.

**Avoid:** copying the old fixed-position canvas/control system, translating whole independent site forks, its US-specific framing, or presenting its advocacy as neutral comparative evidence. Canvas drags and clickable divs do not establish keyboard access; no comparable official-results regression suite was found in inspected teaching files. It is an excellent instructional reference, not a production architecture template or PR allocation oracle.

### P3 — Votelib: best independent exact reference

[Repository](https://github.com/simberaj/votelib). **MIT**, confirmed in `LICENSE.txt`; covered code/test adaptations can be copied with notices. It is Python, so use offline fixtures instead of adding a browser runtime.

**Observed C/R:** dependency-free Python library. `votelib/evaluate/proportional.py` uses `Fraction` for highest averages and remainder computations, supports caps and prior gains, and represents unresolved ties. `evaluate/core.py` composes evaluators; `component/` contains quota/divisor functions; `convert.py` handles ballot transformations. `persist.py` serializes voting-system configuration, not a user's scenario history. `tests/evaluate/test_proportional.py` tests caps, overaward behavior and ties; `tests/real/data/` contains Czech and German election fixtures, including mixed-system examples in the documentation.

Executed directly from the checkout: `HighestAverages('d_hondt').evaluate({'A':100,'B':80,'C':30},10)` → `{'A':5,'B':4,'C':1}`. That is a smoke run, not a full-suite result. No UI, map, undo, mobile or RTL layer exists by design.

**Learn:** make policy choices explicit and test them independently; compare this app's experimental methods against a second exact implementation. Use examples of mixed/biproportional systems to clarify what changing a divisor alone does *not* simulate. **Avoid:** generalizing its election-system configuration persistence into safe untrusted browser imports: the Python deserializer resolves scoped class/callable names. Our strict action union and scenario validation suit our boundary better. Its breadth is stronger; our law-specific Bader–Ofer trace and historical data provenance are stronger for this task.

### P4 — Apportionment: small reusable oracle, with an Israeli trap

[Repository](https://github.com/martinlackner/apportionment). **MIT**, confirmed in `LICENSE`; retain notices when adapting code or substantial fixtures.

**Observed C/R:** compact NumPy-based library in `apportionment/methods.py`; supports largest remainder, multiple divisor methods and quota method, including an optional `fractions=True` path. `tests/test_methods.py` parameterizes method aliases, fraction mode, zeros and known examples. `examples/austria.py` and `examples/israel.py` compare election outcomes; `knesset.txt` stores the Israeli comparison inputs. Direct run `compute('dhondt',[100,80,30],10,fractions=True)` returned `[5,4,1]`. Full suite not run.

**Critical limitation C:** `examples/israel.py` explicitly treats surplus-agreement partners as coalitions and compares the grouped result. That is useful for the national agreement-unit stage, but does not validate qualification of each partner, internal division, statutory lottery, historical remainder variants or candidate caps. Treating it as a complete Bader–Ofer correctness certificate would be wrong.

**Learn:** small readable examples with known official totals, and parametrized edge cases. Borrow an independent expected result only after matching threshold denominators and tie policy. **Avoid:** the example's `eval` of fixture lines in user-facing import code, the default floating path as a guarantee of exactness, and grouping parties before applying the Israeli threshold. UI, edit/undo, sharing, i18n, accessibility and mobile are not applicable; this is a calculation package, not an explorer.

### P5 — ggparliament: reusable visual grammar

[Repository](https://github.com/zmeers/ggparliament). **MIT + file LICENSE**, declared in `DESCRIPTION`; the short licence file supplies copyright details. Preserve both relevant attribution and terms; packaged election data has its own source provenance.

**Observed C:** R/ggplot2 library. `R/parliament_data.R` turns party seat counts into positions for semicircle, horseshoe, circle, classroom and opposing benches. `geom_highlight_government.R` layers an outline behind selected points without replacing party colour; `draw_majoritythreshold.R` is a separate annotation. `draw_partylabels.R` and `draw_totalseats.R` separate labeling from geometry. `tests/testthat/test_parliament_data.R` checks layout output. R was not installed (`command -v R` returned no path), so no local plotting or suite run was attempted; presentation evidence is code/examples, not an observed rendered application.

**Learn:** separate coordinates, grouping, highlight and annotation; use a second channel such as an outline for coalition membership. This fits our rule that party colour belongs to party identity. Keep one 120-seat scale in comparisons. **Avoid:** adding every available chamber layout, translating ggplot coordinates mechanically into responsive React, or copying its fixed annotation coordinates and English labels. Geometry tests do not verify electoral allocation. There is no scenario state, undo, share URL, input control placement, mobile interaction or RTL workflow to copy; those are outside this library's purpose.

### P7 — Open Knesset: preserve identity and time

[Repository](https://github.com/hasadna/Open-Knesset). **BSD-3-Clause** in `LICENSE`; maintain attribution, disclaimer and non-endorsement condition. Official parliamentary records, photos and third-party assets are not automatically BSD.

**Observed C:** Django app organized into `mks`, `laws`, `votes`, agendas and APIs. `mks/models.py` has separate Knesset identity and dated `CoalitionMembership` start/end fields. `templates/include/member_detail.html` links member, party and recorded votes; `knesset/settings.py` defaults to Hebrew and configures i18n. A user scenario/undo/share model is not applicable to this read-oriented portal; modern mobile/accessibility behavior was not verified. It is the strongest local institutional model reference, but does not outperform our seat engine.

### P9 — Israel Election Map: geography is evidence, not decoration

[Repository](https://github.com/Yoavfried/israel-election-map). **Not FOSS as a website.** `LICENSE` splits project-authored open data (`public-data/**` and some manual data under MIT terms) from protected site/pipeline/tests/presentation. `LICENSE-WEBSITE` requires permission for reuse and derivatives. Treat code, colours, text, interaction design and presentation assets as unavailable for copying; independently implement generic map principles. Even open data retains official/third-party source terms.

**Observed C/D:** React/TypeScript/MapLibre frontend plus Python preparation and released CSV/geography. `web/app/src/state/mapLink.ts` validates and encodes election, geography, language, view, selected area/parties and display mode, with tests. `domain/partyComparison.ts` defines two-list balance and a distinct no-vote colour. `domain/mapPresentation.ts` explicitly manages missing records and fallback polygon/marker visibility. Our current locality map should retain its honest aggregation level until stronger joins are sourced. Its map/data scope is deeper than ours; it is not an allocation/scenario engine.

### P10 — Senedd Election Simulator: explicit assumptions, dangerous probability labels

[Repository](https://github.com/jaclarner/senedd_etholiad_sim) · [running app](https://jaclarner.github.io/senedd_etholiad_sim/). **No repository licence grant found in inspected root/package: no copying code/assets without permission.** Open visibility and React dependencies' licences do not establish permission for app code.

The live 1280px screen placed national vote inputs/sliders and a named swing method on the left, baseline-versus-scenario results and majority facts on the right; methodology is a top-level route. `TippingPointsVisualization.js` names donor, recipient, necessary shift and resulting seat transfer; `CoalitionAnalysis.js` shows composition and majority margin. `simulationEngine.js`, `fptpEngine.js` and `metrics.js` separate system/model calculations from UI, though not all explanatory calculations stay out of components.

**Learn:** explain uniform/proportional swing beside its control; show who loses the seat when someone gains it. **Avoid:** its “Highly Possible”/“Less Likely” classes based solely on shift magnitude (<1%, 1–3%, >3%), or hand-assigned ideological compatibility as political probability. National assumptions are not local observations. No full scenario-log/undo, URL roundtrip, official-result regression coverage or Hebrew/RTL support was established from the inspected files. Live site was viewed, not its complete dependency build or tests. Our exact boundary/provenance qualifiers should be stricter than this reference.

### P12 — pollofpolls: uncertainty with explicit inputs and evaluation

[Repository](https://github.com/petres/pollofpolls). **GPL >=3** in `DESCRIPTION`; no code/ports pasted into the MIT project. POLITICO data access/republication terms remain separate from the package licence.

**Observed C:** R package separating HTTP/cache (`R/http.R`), trend models (`trendMean.R`, `trendKalman.R`), plotting (`autoplot.R`, `base.R`), seat simulation (`seats.R`) and out-of-sample evaluation (`accuracy.R`). Trends carry variance; plotting draws ribbons only when it exists. `seats.R` rejects simulation requests lacking variance, returns seat ranges and seat-winning frequencies, documents independent normal draws and their correlation limitation, and supports a reproducible seed through R's RNG. `accuracy.R` truncates polls before each held-out election before refitting. Tests cover seats, accuracy, plotting, downloads and HTTP behavior. R absent, so neither package tests nor plotting were run.

**Learn:** keep deterministic allocations, sensitivity and stochastic uncertainty conceptually separate; attach seed, model and input date to reproducible results; evaluate any future forecasting model out of sample. **Avoid:** claiming independent normal draws model Israeli polling covariance or that a national divisor approximates every mixed/district system. The package explicitly documents excluded direct mandates, overhangs and exceptions. It has no interactive scenario undo/share, phone UI or RTL workflow. For this project's current remit the best contribution is disciplined terminology, not adding polling forecasts.

## What this app already does better — keep it

**Bounded comparison, not a universal proof:** none of the inspected alternatives demonstrates this complete combination. A library may exceed us in arithmetic breadth, a map in geography, and a teaching article in pedagogy. The following are this app's advantages *for the Knesset-explorer task*, supported by the inspected baseline; they are not claims that every alternative lacks every individual feature.

- **Era-specific Israeli law with one inspectable exact allocation trace.** `engine/allocate.ts`, `rules.ts` and retained data builders model more than a generic D'Hondt loop: partner qualification and internal allocation, historical variants, candidate capacity and lottery warning. Neither a generic PR library nor a grouped Knesset example replaces that. Keep the engine independent of React.
- **Reversible structural edits, not only slider arithmetic.** `model/actions.ts` and `app/store.ts` combine merge/split, withdrawal, agreements, candidate/party identity and bloc edits with immutable scenarios, atomic `dispatchMany`, preview and undo/redo. Inspected comparators do not offer this entire law-aware editing surface. Do not regress to DOM mutation or scattered calculator state.
- **Hebrew-first production requirements with English, theme and depth controls over the same result.** P11 is also bilingual, P7 Hebrew-first, and P1 multilingual; none establishes our entire language/direction/theme/three-level contract. Preserve logical CSS and the shared engine. This is a product strength, not evidence that all current responsive/accessibility cases pass.
- **Retained source documents and explicit data qualifications.** Our manifest/build pipeline and documentation distinguish official, secondary, incomplete and pending records. Some map projects have stronger geographic lineage, but none inspected supplies our 1949–2026 era-specific seat-simulation scope. Preserve pending 2026 publication, incomplete unelected rosters and candidate-note qualifications instead of advertising impossible completeness.
- **Threshold and agreement explanations tied to the active scenario.** Existing `Walkthrough.tsx`, list boundaries, glossary, figures, same-scale list bars and soft bloc regions are already more directly suited to this task than a generic parliament donut. Build explanatory experiments around those calculations.
- **Static, account-free operation with portable scenarios and history.** The app already combines local persistence, compressed action sharing, full JSON export, CSV and SVG/PNG. Several alternatives share individual strengths; importing Open Knesset/OWID backend architectures would sacrifice a useful simplicity without a demonstrated need.
