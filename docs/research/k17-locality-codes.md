# K17 locality-code investigation — 6 November 2026

Question: can the 28 March 2006 locality results be joined through an official locality-code field rather than inferred Hebrew names? Decision criterion: an accessible official table with codes and exact vote reconciliation. No such table was verified in this investigation. This is **not** evidence that official locality numbers did not exist.

## Why our rows lack codes

`data/raw/k17/localities.reviewed.json` explicitly identifies `k17-ballots-datagov` as its source. `scripts/lib/historical/k16-k17-common.ts` explicitly sets K17 codes to null and aggregates the official polling records by their names; their schema supplies no locality code, electorate or committee. Consequently those fields are null, rather than fabricated. Names are truncated in that source (for example `מודיעין-מכבים-רעו` and `שושנת העמקים (רסק`). This is a limitation of the retained source, **not** a statement that these localities have no official numbers.

## Decision and reconciliation

Use authorised decision 11b: match the existing normalized Hebrew names to exactly **one CBS code across all retained years**; only a unique truncated prefix of at least eight normalized characters is accepted. Existing עופרה/עפרה spelling handling is reused. Identical English spellings across different codes are sufficient for an English label but **never** for a location. Coordinates still come only from that matched CBS code and retain the actual reference year. No code is written into the official election result rows, and no vote value changes; therefore there is no alternative official coded vote table to reconcile and no claimed exact-vote validation against one.

Result: **1,144 / 1,149 locality rows placed**. Five remain unplaced: דלתון, חברון, נווה אילן, סנסנה, שושנת העמקים (רסק. Envelope votes are excluded from both counts and the missing-location list. Map and table share a bilingual (i) explanation; the displayed legacy claim that no official locality table exists is replaced with the bounded statement that the retained export omits codes. The complete list is also available in the app under “Rows without a mapped location”.

## Conclusion map

- **C1 (documented, high confidence):** retained official datastore has no locality-code column. Supported by live JSON schema; bounded to resource `70f8bc93-8d98-4c20-ad7c-768af713f1c5`, not every historical edition.
- **C2 (unresolved):** an alternative official coded 2006 election table may exist. CEC/NLI/Knesset access barriers and unverified CBS-volume lead prevent a universal absence claim. A legitimately accessible coded table plus exact vote reconciliation would replace the fallback.
- **C3 (implementation evidence):** deterministic unique-name placement is decision-sufficient under 11b; ambiguous identities are withheld. Unit coverage tests and generated coverage verify the published count; this does not prove a historical boundary or station location.
