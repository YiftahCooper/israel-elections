# Locality result map

The Localities tool opens a Leaflet 1.9.4 canvas circle-marker map, with a Table alternative. Hebrew and English partial search normalizes Unicode combining marks (including niqqud), punctuation, spaces and case. Search results and the table provide keyboard alternatives to canvas markers. Selection shows all nonzero historical list votes, shares and reported turnout. Missing-coordinate rows remain selectable, never placed; envelope votes have no location. Pre-2003 elections have no locality results. K17 (2006) retains locality results without codes in the source schema; unique normalized Hebrew-name matches now place 1,144 rows, with the method explained behind (i). See [the source investigation](k17-locality-codes.md); no claim is made that official codes never existed.

## Sources and conversion

Retained `data/raw/demographics/cbs-YYYY.xls`, `.xlsx` and datastore `.json` files supply CBS locality codes, bilingual names and ITM grid reference points. Existing normalized classification files omit coordinates, so the map builder reads the originals. Coded result rows join **by CBS code**. For K17 only, a normalized Hebrew name (or a unique truncated prefix of at least eight letters) must identify exactly one retained CBS code before taking that code’s coordinates; ambiguous matches stay unplaced. No fuzzy matching or English-spelling shortcut is used for positions. Choose the source year nearest the election (earlier on ties); if its coordinates are missing, try other retained years for that code. Each published location records the actual source year and aliases. Later coordinates can therefore serve as reference points for historical localities; these are not reconstructed historical boundaries or polling stations. No geocoder is used in the data build.

CBS concatenates equally sized easting and northing fields: eight digits mean 100 m, ten mean 10 m, twelve mean 1 m. Decode each half and scale to metres. Transform EPSG:2039 (Israel 1993 / Israeli TM Grid) with proj4 2.22.0 using the published EPSG:9676 seven-parameter position-vector transformation, including the GRS80 ellipsoid, TM origin/scale/false offsets and datum shift. See the exact definition in `src/data/locality-coordinates.ts` and [EPSG definition](https://epsg.io/2039). Tests compare three points against independent PROJ/pyproj 3.7.2 values at 1e-7 degrees. Numerical agreement is not real-world accuracy: EPSG transformation accuracy is about 0.5 m and source reference precision can be 100 m. Reject absent/malformed/out-of-region grids; never invent a coordinate.

To regenerate, install Python `xlrd==2.0.2` and `openpyxl==3.1.5` into `.backup-scratch/python`, install npm dependencies with the lockfile, then run `PYTHONPATH=.backup-scratch/python node scripts/build-locality-map.ts` from the repo root. No network is needed after dependencies are installed. Outputs `public/data/kNN-locations.json` and `locality-map-coverage.json` are retained build assets. Scratch dependencies/logs are disposable. This workflow does not change global Python configuration.

## Colour semantics

These are historical local votes with the **current scenario** list/bloc attribution, not a geographic simulation of national vote edits. A merged list gets its origins' local votes. Split origins distribute by current scenario national vote proportions (equally if all weights are zero). Deleted historical lists remain unassigned. Winners are pluralities of valid votes, including below-threshold lists. Ties, zero votes and unassigned winners are neutral grey.

There are no constituent-party or candidate ballots within a joint list. For a list spanning blocs, apportion its historical local votes by its current elected members' bloc fractions using `allocationOf` and **`seatBlocsOf`**, preserving candidate override → party override → list bloc precedence. Lists with no elected seats use their list bloc. This is an explicitly labelled estimate, not evidence that individual voters voted for a constituent party. Scenario edits recalculate the colours; changing bloc names/colours updates the legend. Winning-list mode applies the same origin mapping without bloc apportionment. Selecting a locality shows the leading group, its lead over the runner-up in percentage points of valid votes and in votes, and (in bloc mode) each bloc's total; dot tooltips carry the same lead.

The basemap is context: its tile pane alone is desaturated, and in dark theme inverted (CSS filter), so party colours stand out and the map is not a bright panel in a dark page (owner, 5 Nov 2026). Markers keep a white outline, legible in both. If tiles fail to load (for example a sandbox that strips the Referer, which the OSM policy requires), the map says the background could not load; dots and search keep working.

## English names

OSM tiles label places in the local script, so in English mode the app draws its own labels for the localities (in Hebrew mode only at zoom 9 or less, where the tiles name almost no Israeli localities, so labels never duplicate): CBS English names, larger localities first by registered voters (cast votes when unknown), more at higher zoom, never overlapping and never cut by the frame. `scripts/build-locality-map.ts` also writes `public/data/kNN-locality-names.json`, index-aligned with the result rows (`src/data/locality-names.ts`). A row takes the CBS English of its code, preferring a record with the row's own Hebrew name (a merged locality keeps the name of its era) and CBS's mixed-case spelling over the older all-capitals files. Rows without a code (all of 2006) join by exact spelling-insensitive Hebrew name (niqqud, punctuation, CBS asterisks and doubled yod/vav ignored, within words) or, for names the 2006 file truncated, by a unique prefix of at least eight letters; a match must be a single CBS code or one English spelling, otherwise no name is taken. English labels can accept identical English spellings across several CBS codes; positions cannot. K17 positions use the same Hebrew normalization and prefix threshold but require exactly one CBS code. Inferred identities are retained as row-index location keys, never written into the official result rows. One evident CBS typo is corrected from the same list, and one 2006 spelling (עופרה/עפרה) is aliased. Rows absent from every retained CBS list (Hebron, six 2003 localities later merged, one truncated 2006 name) carry project transliterations in CBS style, listed in the build script and shown with a dotted underline. Address search asks Photon for English (`lang=en`) in English mode; Photon has no Hebrew output.

Tile options checked on 5 Nov 2026: CARTO basemaps now return "API key required"; the German OSM server labels in German transliteration; Esri's keyless gray canvas tiles have dark and light versions and an English-only label layer, but their licence for anonymous use from non-Esri software is unclear (Esri Master License Agreement), so they are not used without the owner's decision.

Leaflet's zoom buttons and keyboard handler refocus the map with a plain `focus()`, which scrolled a partly visible map into view (12–54 px per zoom click). The map uses a zoom control subclass and a capture-phase focus, both with `preventScroll`.

## External services

[Photon public service](https://github.com/komoot/photon#demo-server) was selected because it permits reasonable low-volume requests; unlike Nominatim's application-wide 1 request/s ceiling, it does not require a cross-user rate limiter unavailable on a purely static GitHub Pages site. Explicit address submission only: no autocomplete, background queries or bulk geocoding. A shared per-page 1.1-second guard, memory cache, disabled pending submit and timeout limit traffic. User sees provider/data attribution and that the address is sent externally. Up to five address alternatives are shown; the user chooses one, then the app finds the nearest **mapped election locality reference point** by great-circle distance, reports straight-line km, and selects its results. This is not administrative address containment. Photon availability/accuracy is not guaranteed; failures leave local search usable. Move to a private/paid instance if traffic grows.

[OSM tile usage policy](https://operations.osmfoundation.org/policies/tiles/) is observed with the standard HTTPS URL, visible contributor attribution, browser Referer, normal HTTP caching and viewport-only tile loading. No bulk prefetch, offline download, cache bypass or service worker is added. API contracts were checked against [Leaflet 1.9.4 documentation](https://leafletjs.com/reference-1.9.4.html).

## V4 implementation — 7 November 2026 (boundary work incomplete)

The raster-background and inverted-dark-style descriptions above are superseded. Leaflet 1.9.4 still owns the result dots, collision-managed DOM labels, selection, keyboard zoom and address lookup. Its background is now MapLibre GL JS 5.24.0 through the compatible 0.1.3 Leaflet binding. The binding's retained package README/types and [official integration guide](https://github.com/maplibre/maplibre-gl-leaflet/tree/v0.1.3) establish the supported `maplibreGL` / `getMaplibreMap` API; the current main-branch README describes a newer ESM adapter and must not be copied into this version.

`locality-basemap.ts` is dynamically imported only when the map mounts; its approximately 1.03 MB uncompressed JS (275 KB gzip in this build) is a separate map-only chunk. No MapLibre runtime is added to another tab's initial load. Each theme fetches the corresponding public OpenFreeMap Positron/Dark style, then strips **all** symbol layers and boundary layers before creating the vector map. This removes road/water/airport labels as well as place names and POIs, including labels in neighbouring countries. No provider label can be underneath or duplicate the retained names. Attributions for OpenFreeMap, OpenMapTiles and OpenStreetMap remain visible even when the style fails. There is no raster inversion, tile prefetch or offline cache. Failure leaves election dots and local search available with a bilingual notice.

CBS/result labels now appear at every zoom in both languages, using the existing row/code keys (including k17 inferred location keys), electorate-size ranking, zoom thresholds and rectangle collision checks. Every **placed** row has a CBS English name; the new coverage test checks every retained election, forbidding project transliterations among placed rows. Hebrew uses the actual result-row spelling, preserving consistency with the table. English results no longer append a Hebrew subtitle, and asynchronous name loading uses an English placeholder. Hebron still has no retained coordinate; no point was guessed. Historical Gaza localities appear only where retained result coordinates exist.

The map intentionally hides provider boundaries rather than presenting an unverified provider line as authoritative. A short “Boundary lines unavailable” label opens an explanation. This does **not** fulfil the requested line overlays/legend: [map-lines.md](map-lines.md) records candidate sources, the numerical disagreement for the two Green Line sections, withheld overlays, bilingual draft copy and reproduction instructions. The feature must not be described as complete until those overlays pass the owner's independent-geometry gate.

Fallback, documented only: retain a versioned regional Protomaps PMTiles extract on owner-controlled storage (for example R2 with Range/CORS configured), its exact extraction bounds/date, checksums, style/font licences and attribution; use the same symbol/boundary filtering and CBS labels. This requires an explicitly maintained source artifact, not an assumption that a future download is reproducible. No bucket, deployment or fallback download was created.

Screenshots are in `.backup-scratch/v4/`: `k{26,17,25,1}-{he,en}-{light,dark}-{1500,1024,390}.png` and `{jerusalem,hebron,golan,gaza}-{he,en}-{light,dark}-{1500,390}.png` for k26, with `k17-` prefixed for the same regional matrix in 2006. Captures show the actual viewport after scrolling the map into view; full-page WebGL captures were rejected because off-screen compositing could leave partial frames. Regional views use Jerusalem, Qiryat Arba, Qazrin and Sederot as existing mapped reference points; the “hebron” view does not invent a Hebron coordinate and the “gaza” view includes Gaza's surroundings rather than asserting a locality label for Gaza City. Screenshot scripts and diagnostic logs remain disposable scratch.

V4 validation: TypeScript and production build pass; 103 unit files / 967 tests pass, six targeted map browser tests pass, and the full 554-test browser suite passes with two workers (port 5497).
